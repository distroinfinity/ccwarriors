# Data Models

Schema lives in `apps/server/src/db/schema.ts` (Drizzle). Postgres in production; when `DATABASE_URL` is unset, `db/index.ts` boots an in-memory PGlite instead — same schema, zero setup. Migrations are generated by drizzle-kit and run automatically on every Railway deploy via `railway.json`'s `preDeployCommand: pnpm --filter server db:migrate`.

## `users` — the warrior row

Identity (`githubId`, `githubLogin`, `avatarUrl`, `xHandle`), the CLI credential (`cliTokenHash` — sha256 of the bearer token, rotated on every login), and the board aggregates the leaderboard store hydrates from: `cost30d`, `costAllTime`, `tier`, `toolBreakdown` (jsonb per-tool `{cost30d, costAllTime}`), `hasBreakdown`, `lastSyncedAt`.

Notable columns:

- `flaggedAt` / `flagReason` — shadow quarantine. Flagged users keep syncing; they just leave the boards.
- `insightsMode` (`off | deep`) is the source of truth for deep mode; `insightsConsent` is kept consistent (`consent = mode === 'deep'`) for older code paths. `insightsVisibility` (`public | private`) gates who sees insights.
- `consentVersion` — the deep-disclosure version the user acknowledged. Null = pre-versioning (treated as v1). v2 added prompt-text extracts and redacted transcripts.
- `craftScore` / `trustTier` (0 unverified, 1 local-git) — recomputed eagerly on every `/insights/deep` upload so reads never replay pillar math.
- `githubAccessToken` — `read:user`-scoped OAuth token persisted at web login for server-side public-data reads (5000 req/h per token); nulled on 401.
- `pinnedCards` — up to 4 card keys the owner pinned to the front of their deck.
- `installSource` — first-touch channel attribution (`?ref=` → installer → enlist), never updated.

## `usage_days` — the priced ledger

Raw per-day token counts (`inputTokens`, `outputTokens`, `cacheCreationTokens`, `cacheReadTokens` as bigints, plus `modelBreakdown` jsonb of per-model `ModelTokens`) and the **server-computed** `cost`. Client dollar estimates are never stored here. One row per machine so multi-machine users aggregate by sum instead of last-write-wins flip-flopping — which would also false-trip the settled-day-growth gate (`schema.ts:170`).

## Insights and story tables

- `user_insights.payload` is the aggregate `InsightsPayload` (histograms, rates — counts only, no text). Since the deep path landed, the server **derives** this row from `user_deep_sessions` on every deep upload, so one upload feeds both archetype/efficiency code and Craft Score.
- `user_deep_sessions.sessions` is the `SessionRecord[]` (per-session counts, timing summaries, hashed git outcomes, and edited-file `extensions` for the builds-with stack) plus optional `extras` (`maxConcurrentSessions`, `topPrompt`). The route schema accepts the extras, but the current CLI `postInsightsDeep()` sends only `windowDays` + `sessions`, so consumers must treat extras as usually absent. These records drive Craft Score, outcome economics, session depth, and the stack panel.
- `story_sources` holds redacted transcript payloads **only until generation**: the story service deletes the row after writing `user_stories.doc` (`StoryDoc`: tagline, narrative, arc, whatYouBuilt, decisionPatterns, strengths, growthAreas, aiArchetypes, crypticPrompt, sessionsAnalyzed, windowDays). That purge is a documented user-facing promise — do not "optimize" it away.

## `github_stats`

`status` (`ok | error`), `data` (jsonb `GithubStats`: followers, stars over top-100 owned repos, merged PRs, commit streaks, 40-day window counts), `fetchedAt`. The refresher serves stale forever: `data` survives later failed fetches; `status` + `fetchedAt` drive retry backoff (6h fresh TTL, 30m error retry — `lib/github-stats-service.ts:11`).

## Shared payload types

`schema.ts` exports the wire types consumed across the stack: `ModelTokens` (per-model token quad), `ToolBreakdown`, `InsightsPayload`, `SessionRecord`, `GithubStats`, `StoryDoc`. The CLI has its own mirrors of the client-side shapes — see [Payload Schemas and Compatibility](../api/payload-schemas-and-compatibility.md) for the contract.
